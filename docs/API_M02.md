# Milestone 2 Public API and Domain Contracts

## Scope and compatibility

M02 publishes platform-neutral Java 8 contracts only. All five artifacts use class-file major 52 and compile on the approved Temurin 8/11/16/17/21 matrix. They contain no Bukkit, Paper, NMS, proxy, Redis, SQL, filesystem, Discord SDK or runtime-configuration dependency. Runtime adapters, provider selection, persistence, configuration, commands, permissions, GUIs and gameplay begin in later milestones.

`ApiVersions.CURRENT` is `1.0.0`; `ApiVersions.SUPPORTED` is `[1.0.0,2.0.0)`. Public contracts follow semantic versioning. Incompatible changes require a new major API range and metadata validation failure for unsupported consumers. Deprecation must name its replacement and remain available for at least the supported major-version window; M02 introduces no deprecated member. `build/api-signature-baseline.txt` is the authoritative initial JVM binary baseline.

## Contract rules

- Public inputs are non-null unless a method explicitly documents a nullable return, such as `ApiEvent.Decision.cancellationReasonOrNull()`.
- Validation failures caused by external metadata are reported as sorted `ExtensionValidation.Issue` values. Programmatic invariant violations fail immediately with the documented specific exception. Expected provider or application failure uses `Result<T>` and `ApiError`, not generic exceptions.
- Value objects are immutable. Collections returned by metadata, capability and registry contracts are sorted where ordering is meaningful and unmodifiable.
- Event metadata contains typed event/type/correlation IDs, occurrence time, per-stream sequence, schema version and callback thread context. Listeners must obey that context and must not block an owner thread.
- Provider and extension lifecycle operations are asynchronous. `start`, bounded `drain` and `stop` return completion stages carrying typed results; hidden blocking joins are forbidden.
- Provider calls declare capabilities. Missing mandatory capability is an explicit typed failure, never `null`, silent fallback or a service-locator lookup.

## Identity, time, results and events

UUID-backed IDs are `ArenaId`, `MapId`, `MatchId`, `ReplayId`, `CaseId`, `EventId`, `CorrelationId` and `PlayerId`. Namespaced IDs are `ExtensionId`, `DefinitionId`, `GuiPageId`, `CapabilityId`, `ContentPackId`, `ResourceId`, `GeneratorTypeId`, `PrivateGameModifierId`, `ProviderId`, `EventTypeId` and `IdempotencyKey`. Parsing is canonical and rejects malformed, uppercase or cross-type identity use.

`TimeSource` supplies wall-clock instants for metadata and deterministic tests. `MonotonicTimeSource` supplies duration/order measurements. Wall-clock values must not decide elapsed timeout correctness.

`Result<T>` contains exactly one success or `ApiError` branch. `ApiError` has a stable typed code, localization key and retry disposition. `EventMetadata` and `ApiEvent.Decision` define ordering, schema, threading and cancellation without exposing platform objects.

## Extension metadata

The M02 exchange format is UTF-8 `key=value`, schema version 1, read through a caller-supplied `Reader`. The SDK does not open files or load classes. Required keys are extension ID, display name, semantic version, entrypoint, API/product ranges and inclusive Minecraft range. Optional repeated declarations cover dependencies, required APIs, provided capabilities, permissions and configuration keys.

The reader rejects unknown, duplicate, missing and malformed keys. The validator rejects unsupported API/product/Minecraft ranges, duplicate or self dependencies, missing required dependencies, incompatible dependency versions, duplicate extension IDs, permissions or configuration keys. Reports have deterministic issue ordering. Valid and invalid examples live under `sdk/zbw-sdk/src/test/resources/extensions`.

Extensions progress through `DISCOVERED`, `VALIDATED`, `STARTING`, `ACTIVE`, `DRAINING`, `STOPPED` or `FAILED`. Runtime discovery, class loading and activation are deliberately outside M02. Metadata validation always precedes future activation.

## Content, generators and RESOURCE SCARCITY

`ContentRegistry` defines typed definitions, pack metadata, registry versions and provider contracts. `ImmutableContentRegistry` rejects duplicate IDs and publishes a stable sorted snapshot. M02 does not parse runtime content configuration or perform migrations.

Generator definitions use `GeneratorTypeId` and `ResourceId`. `ResourceGenerationProfile` independently maps any native or custom resource to a bounded decimal `GenerationMultiplier`. `ResourceScarcity` reserves the stable modifier ID `zartra:resource_scarcity`, exposes `SCARCE`, `REDUCED`, `NORMAL`, `ABUNDANT` and `EXTREME` preset identities, and supports custom profiles. Numeric preset balancing, host GUI, permissions, commands, events, placeholders and runtime application remain M03/M20 work.

## Discord contracts

`DiscordIntegrationApi`, `DiscordProvider`, `DiscordEventEnvelope` and `DiscordCapabilities` implement the M02 portions of `ZBW-DISCORD-001/002/005` and foundations for `001..008`. Envelopes are immutable and carry event identity, idempotency, sensitivity, required capability and deadline. `PROHIBITED_EXTERNAL` is an explicit sensitivity class. Queries are read-only and carry caller identity, correlation and deadline.

The SPI has asynchronous lifecycle/delivery, typed delivery classification and provider extension metadata. No bot, webhook, transport, token, secret resolver, no-op runtime or retry/outbox engine is implemented in M02. Discord remains optional by contract and no Discord SDK enters the Minecraft process.

## Verification

`tools/validation/m02_architecture.py` enforces module dependencies and forbidden imports. `tools/validation/api_compatibility.py check` compares compiled public/protected JVM descriptors with the committed baseline and verifies Java 8 bytecode. Unit tests cover canonical IDs, equality/hashing, parsing/serialization boundaries, null/malformed input, versions, results, clocks, event metadata/cancellation, capabilities, provider metadata, content duplicates, generators, RESOURCE SCARCITY, extension fixtures/duplicates/unsupported API versions and Discord envelope/provider contracts.
